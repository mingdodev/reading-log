## 구역

### 일부 하드웨어 장치는 특정 메모리 주소로만 DMA를 수행할 수 있다. 왜?

- DMA 컨트롤러 또는 장치 자체가 가진 주소 버스의 비트 수가 시스템 전체 주소 공간보다 작을 수 있기 때문이다.

예: 시스템은 64-bit 주소 공간을 사용하는데, 오래된 ISA 버스 장치의 DMA 컨트롤러는 24-bit 주소만 표현 가능 -> 표현할 수가 없으니까, 접근을 할 수가 없다.

```
물리 메모리 (예: 8GB RAM)
물리적 메모리 주소 범위에 있는 페이지들의 묶음을 플래그로 구별해둠
┌──────────────┐ 
│  ZONE_DMA    │  0 ~ 16MB    ← ISA 장치도 접근 가능한 구간
├──────────────┤
│  ZONE_DMA32  │  16MB ~ 4GB  ← 32-bit DMA 장치까지 접근 가능한 구간
├──────────────┤
│  ZONE_NORMAL │  4GB ~ 8GB   ← 최신 장치만 접근 가능한 구간
└──────────────┘
...
```
DMA에 사용될 페이지는 물리 주소가 고정되어 있어야 함! CPU를 거치지 않고 직접 메모리에 접근하므로, MMU의 가상→물리 변환을 받지 못하기 때문.
구형 장치는 낮은 주소만 접근 가능.
이 두 조건을 동시에 만족하려면 낮은 물리 주소를 사용해야 함.
따라서, ZONE_DMA를 낮은 주소에 만들어 예약해 뒀다.

cf. 장치는 자신의 주소 제한을 알고 있으므로, 메모리 할당할 때 플래그로 직접 지정해서 요청

```c
// 드라이버 코드 안에서
kmalloc(size, GFP_DMA);    // "16MB 안쪽에서 줘" 라고 명시
kmalloc(size, GFP_DMA32);  // "4GB 안쪽에서 줘" 라고 명시
kmalloc(size, GFP_KERNEL); // "아무데나 줘"

// 또는 DMA 마스크를 설정: 이 장치는 32-bit 주소까지만 DMA 가능하다고 커널에 등록
dma_set_mask(dev, DMA_BIT_MASK(32));
```

그리고, dma시 페이지가 할당되면 그 페이지의 물리 주소를 고정(pin)하는 작업도 수행함. (필수!!)

### 일부 아키텍처에서는 가상적으로 접근할 수 있는 것보다 더 많은 양의 메모리를 물리적으로 접근할 수 있다. 따라서 일부 메모리는 커널 주소 공간에 상주할 수 없다. 왜?

원인: 커널 가상 주소 공간의 크기 한계
32-bit 아키텍처(예: x86 32-bit)를 예로 들면:

전체 가상 주소 공간: 4GB (2³²)
전통적 분할: 유저 공간 3GB + 커널 공간 1GB
커널이 직접 매핑(1:1 linear mapping)할 수 있는 물리 메모리: 최대 1GB 미만

만약 물리 RAM이 4GB라면, 커널의 1GB 가상 공간으로는 나머지 물리 메모리를 영구적으로 매핑할 수 없음.

해결책: High Memory (highmem)

```
물리 주소
┌─────────────┐
│  highmem    │  ← 커널 가상 공간에 항상 매핑되지 않음
│  (1GB~4GB)  │     필요할 때만 임시로 kmap() 으로 매핑
├─────────────┤
│  lowmem     │  ← 커널 가상 공간에 1:1로 영구 매핑 (실제로 896MB정도 씀)
│  (0~1GB)    │
└─────────────┘
```
lowmem: 커널 가상 주소에 항상(permanently) 매핑되어 상주함
highmem: 필요할 때 kmap() / kmap_atomic()으로 임시 매핑, 다 쓰면 해제 (오.. 382에 다시 나오네)

> 64-bit 아키텍처는 가상 주소 공간이 실제 RAM보다 충분히 크기 때문에, 사실 이 개념은 레거시가 되었다고 함.

## vmalloc()

### 휴면 불가능한 플래그를 쓰면 어떻게 동작해? 반드시 한번에 작업을 동기로 처리해?

"동기로 처리한다"기보다는 "메모리를 구하기 위해 잠드는 행위를 하지 않는다" 는 의미입니다.
GFP_KERNEL은 메모리가 부족하면 커널이 잠든 뒤 다른 프로세스를 스왑 아웃시키거나, 캐시 페이지를 비우거나, 디스크 I/O를 기다리는 등의 작업을 할 수 있습니다. 이 모든 과정이 "휴면"입니다.
GFP_ATOMIC은 이런 과정 없이 지금 당장 빈 페이지가 있으면 주고, 없으면 그냥 NULL 반환합니다. 그래서 인터럽트 핸들러처럼 절대 멈추면 안 되는 곳에서 쓸 수 있는 대신 실패 가능성이 높습니다.

vmalloc과 인터럽트
맞습니다. vmalloc이 인터럽트 컨텍스트에서 쓸 수 없는 이유가 휴면 가능성 때문입니다. 가상 주소와 물리 페이지를 연결하기 위해 페이지 테이블을 조작하는 과정에서 물리 페이지를 새로 할당받아야 하는데, 이때 내부적으로 GFP_KERNEL처럼 동작하므로 휴면이 발생할 수 있습니다.
